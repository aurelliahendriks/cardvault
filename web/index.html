Ranked by money at stake, not by card value — a A$60 rookie shedding value weekly outranks a A$7,000 Messi that isn't going anywhere.

Where it sells best

Median sold price per marketplace region, net of that venue's fees and price realization, compared with your home market. This is measured from comps, not assumed — so it stays empty until ingest has collected some, and any region with fewer than three sales is labelled a one-off rather than plotted as a trend.

Where sellers are

Seller location as eBay reports it: a country, usually a state, sometimes a city, often nothing — which is why the coverage figure is shown. There is no suburb-level sold-price source anywhere, so this stops where the data does. And note it is where the seller is, not the buyer.

Where the value sits

Share of collection value by set section. The tail is folded into “Other” rather than given its own colour — a generated ninth hue is indistinguishable under colour-blindness.

How much of this is real

Value backed by observed sold comps versus value resting on an estimate. The second number is the one to be suspicious of.

Biggest 30-day movers

Only cards with three or more sold comps — a “move” on one sale is noise.

Value by price band

Where your money is concentrated. Cards under A$5 are a postage problem, not an asset.

Value by card type

Base, insert, autograph, promo. Where the money sits by category rather than by set section.

Value by box it came from

Only what you've recorded. Once a few boxes are logged this is what tells you whether hobby boxes actually returned more than blasters did.

Realised sales, net of fees

Weekly net proceeds from your own logged sales — the ground truth for calibrating every fee and realization assumption in the model.

Net proceeds by venue

Headline prices across marketplaces are misleading. This subtracts final value fees, the international transaction surcharge, postage from Australia, and the demand drag from buyer-side import duty — then applies each venue's price realization and value band.

Community channels

A different question from “which marketplace”. A A$3 base card is a loss on eBay and a fine sale inside a player lot; Mexico squad cards clear above global price in Mexican groups.

Ask about your collection

Source health

Check here first when prices stop moving. Runs but zero new items usually means a site changed its markup; errors mean credentials or blocking.

Model calibration

The rarity, condition and market scores describe; they do not decide. Sell/hold stays explicit expected-value arithmetic you can argue with. The scores are logged beside every decision so they can later be tested against what actually happened — and until there is enough data to do that honestly, the weights stay frozen and say so.

Club data health

Clubs are a snapshot — Panini prints the national side, so club comes from Wikidata or from you, and squads change every transfer window. Freshness changes what the app claims, never what it shows: the filter keeps every player, and a club past 45 days just stops asserting certainty.

Rarity effects

Scarcity is drawn as an effect over the artwork rather than as different artwork. One asset per card, one CSS class per tier — which is why adding a parallel costs nothing. Print run decides the tier before the colour word does: a Gold /10 is treated as a /10.

Import sold comps

Headers: title, price, currency, shipping, sold_at, marketplace, and optionally city, region, country. Manual comps carry full trust weight — this tier needs no API keys at all. The location columns are the only way a local sale gets on the map: a card sold at a Melbourne meet or in a Facebook group exists in no API, so if you do not type it here that sale is invisible to the model and the channel it came through can never be compared with eBay.

Import your collection

CSV, or the .json save file from the old HTML tracker — quantities, price overrides and the sales log all carry across.

Bulk add

One card per line, written however you would say it. The same matcher that reads eBay titles reads these, so surname and number is usually enough — mora 214, messi kaboom psa 10, yamal gold /10. Add x3 for quantity and @4.50 for what you paid.

Admin key needed

This CardVault has ADMIN_API_KEY set in .env, so anything that changes data has to present it. Reading is open; writing is not. Paste the value from your .env — it is kept in this browser and sent only to your own server.

Or clear ADMIN_API_KEY in .env and restart if you would rather not have a key at all.
